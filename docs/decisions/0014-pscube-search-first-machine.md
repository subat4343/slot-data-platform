# ADR-0014 P's CUBE: 台番号検索で先頭の台を開き、「次台 >>」だけで最後まで進む

ADR-0013 のうち、台詳細の開始台と巡回方向の決定を置き換える（機種一覧のスクロールはそのまま）。

## 状況
- ADR-0013 の方式（先頭の機種の先頭の台から「次台 >>」、端に達したら機種一覧へ戻って開始台を開き直し「<< 前台」方向）で、2026-11-13 23:30 の巡回が、戻る操作の途中（機種画面の台番号リンクが表示されない）で止まった。233 台中 56 台（0236〜0356）しか取れなかった。
- 開始台が台番号の途中になるため、戻る処理が 1 回失敗すると開始台より前の台がすべて取れない。`--resume` でも取得済みの区間をたどり直していた。
- ユーザーから「台番号で探す」で 0001 を開き、「次台 >>」だけで進む方式の提案があった（2026-11-14）。

## 決定
- 機種一覧を最後までスクロールして保存したあと、画面の「台番号で探す」タブ・入力欄・送信ボタンを使って台番号 0001（options.first_machine）を検索し、台詳細を開く。送信先の URL を直接開くことはしない。送信は画面遷移 1 回として 30 秒間隔を守る。
- 0001 が開けない（該当なし、台詳細に移らない）ときは、これまでに観測した最小の台番号で検索し直す。それでも開けなければ `FETCH_FAILED`（kind=search_failed）を記録し、先頭の機種の先頭の台から入って「次台 >>」方向だけを辿る。
- 以降は「次台 >>」だけを押し続ける。「次台 >>」が無い、押しても台が変わらない、一周して既に見た台に戻る、のいずれかで終える。前台方向へ戻る処理と、機種一覧に戻って開き直す処理はなくす。
- 押しても台が変わらないまま一覧の台数合計に届いていない場合や、操作がタイムアウトした場合は、現在の台を検索で開き直してもう一度押す（1 回の巡回で 2 回まで）。拒否（error(451) など）のときは従来どおり打ち切る。
- `--resume` では、再開元で解析まで済んだ台詳細のうち最大の台番号を検索で開き、そこから「次台 >>」で続ける。取得済みの区間はたどり直さない。
- 機種画面（日別 BONUS 回数）は通常の巡回では開かない（台詳細の BIG＋REG で得られる）。

## 追記（2026-11-14 午後）
- 手動実行（run 01a1d809…）で、「次台 >>」が 0186 から先へ進まず、233 台中 123 台で `succeeded` として終わった（取りこぼしが記録に残らなかった）。サイト側で「次台」が途中の台で止まる理由（区画の切れ目など）は HTML からは分からない。
- 対応: 進めなくなったら現在の台を検索で開き直して 1 回押し直し、それでも進まなければ、これまでに観測した台番号のうち次に大きい台を検索で開いて続ける（観測が無ければ最後の台番号＋1 から 5 件まで試す）。切れ目が複数あっても同じ手順で最後まで進む。
- 想定台数に届かないまま終わったら `FETCH_FAILED`（kind=walk_incomplete）を記録し、run は `partial` になる。
- 検索での開き直し、切れ目からの再開、巡回の終了理由（end / wrapped / stuck / limit など）を INFO ログに出す。
- 存在しない台番号の検索は画面が変わらないため、検索の待ち時間の上限を 60 秒から 20 秒に短くした。

## 影響
- 画面遷移は約 235 回（一覧 1 + スクロール約 7 + 検索 1 + 台詳細約 233）。約 2 時間。
- 「台番号で探す」の挙動は 2026-11-14 に実機で確認した（0001 → 台詳細へ直接移る、9999 → 画面が変わらない、検索で開いた台詳細でも「次台 >>」で 0002 に進む）。存在しない台番号では台詳細に移らないまま待ち時間の上限（60 秒）まで待ってから次の候補に進む。
